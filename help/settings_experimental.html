Experimental

This page is a top-level Settings category immediately above Plugins and collects experimental sharing, transfer, hashing, RTF0, defensive protocol, and application theme controls. The controls are divided among the Chat and sharing, Transfers and hashing, Protocol limits, and Theme tabs.

Application theme

Color mode
Follow Windows uses the system application preference where Windows provides one. Light and Dark select a mode explicitly. On Windows 7 and Windows 8, Follow Windows uses the native light appearance because those versions do not expose an application dark preference.
Dark theme palette
The preset list provides several built-in dark palettes and every valid XML theme found in the per-user Themes directory. Save XML writes the current palette and installs it in that directory, while Import XML validates an existing file and copies it there. Custom represents a palette that does not match a loaded preset and does not save it automatically. Open folder opens the directory so XML files can be added or edited directly; use Reload afterward. Editing an individual color selects Custom. The reset button restores the default dark palette. Palette selection sets the background, surface, text, disabled-text, border, accent, and selected-text colors used by the dark theme. DC++ uses the same manual palette renderer on Windows 7 and later; it does not require a Windows 10 dark visual style. Native control behavior, dimensions, input, and accessibility are retained while DWT paints windows, menus, tabs, buttons, check boxes, group boxes, lists, headers, status and tool bars, scroll bars, and other framework chrome. The renderer reproduces hot, pressed, checked, default, disabled, keyboard-cue, and focus states. Chat formatting and other colors selected under Appearance > Styles remain application content and are not replaced by the chrome palette.
Theme XML format
Theme files are UTF-8 XML documents no larger than 64 KiB. Each color is an RGB value in #RRGGBB form: 
<?xml version="1.0" encoding="utf-8"?>
<DCPlusPlusTheme Name="Example dark">
  <Palette Background="#202020" Surface="#2D2D30" Text="#F1F1F1"
    DisabledText="#A0A0A0" Border="#494949" Accent="#0078D7"
    HighlightText="#FFFFFF" />
</DCPlusPlusTheme>
High contrast
Windows high contrast takes precedence over every color-mode and palette choice. DC++ then uses the current Windows system colors so contrast and accessibility choices remain under operating-system control.

Rich text and temporary shares

Enable ADC RTF0 CommonMark chat
Advertise ADC RTF0 support on hubs and direct CCPM connections and render its safe CommonMark dialect. Supporting chats provide the RTF0 editor and drag-and-drop attachments.
Enable temporary file sharing in chats
Allow unshared files dropped on any connected ADC or NMDC hub or private chat—and files selected by the RTF0 editor—to be hashed and exposed by exact TTH for that route. Plain and RTF0 chat displays keep the magnet URI visible and clickable and show its human-readable file size; RTF0 routes may additionally render formatted attachments and inline images. Disabling this prevents new temporary shares and makes existing temporary entries unavailable to search or transfer while retaining them in the management list until removed or the application exits.
Insert dropped image files as inline media
Use RTF0 inline-image syntax for recognized BMP, GIF, ICO, JPEG, PNG, TIFF, and WebP files when the chat supports RTF0. Plain ADC and NMDC chats always receive an ordinary magnet link.
Rich text message size limit
Maximum UTF-8 size of an incoming or outgoing ADC RTF0 rich text message, in KiB. Larger incoming messages are replaced with an omission notice; larger editor drafts cannot be inserted into chat. Minimum: 1 KiB. Default: 64 KiB.
Clickable chat link length limit
Maximum URL or magnet URI length that will be turned into a clickable chat link. Longer links remain visible as plain text. Minimum: 1 character. Default: 256 characters.
Maximum temporary shares
Maximum number of temporary RTF0 attachments retained for the current application session. Adding another entry removes the least recently used entries first. Minimum: 1. Default: 256.
Active temporary shares
Lists the session-only files currently addressable by exact TTH, including their route and local path. These files appear in search results only on the hub or CCPM route where they were added, remain absent from file lists and share totals, and can be downloaded by TTH only from that route. Remove selected entries, clear the full list, or refresh file availability from here.

Multi-connection transfers (MCN)

Maximum download connections per user
Limits simultaneous ADC MCN1 download connections opened to one user. The remote limit is also respected, and segmented downloading plus MCN1 support are required.
Maximum upload connections per user
Limits simultaneous ADC MCN1 upload connections accepted from one user. This value is advertised to MCN1-capable peers and does not increase upload slots.

Hashing and share database

Maximum hash speed
Limits file hashing speed in MiB/s. Zero means unlimited.
Hash database write batch size
Number of SQLite hash database row changes grouped into one transaction. Larger values improve bulk hashing throughput; smaller values commit newly hashed files sooner.
Verify hash database on startup
Runs a quick SQLite integrity check when the hash database opens.
Compact hash database after rebuild
Compacts SQLite storage after a hash database rebuild.
Use cached share tree on startup
Loads a validated cached share tree before the background filesystem refresh completes.
Verify / Full check / Optimize / Compact
Runs hash database maintenance immediately. Verify uses SQLite quick_check, Full check uses integrity_check, Optimize updates query planning hints, and Compact checkpoints the WAL and reclaims unused space.

Protocol resource limits

These limits protect DC++ from excessive memory, connection, and packet use. The defaults are recommended for normal use. Lower values can reject legitimate traffic; higher values increase resource usage and exposure to denial-of-service traffic. Changes apply to new operations without restarting DC++.

Queued protocol data limit
Maximum unsent protocol data retained for one socket, in KiB. The socket is disconnected when another write would exceed the limit. Minimum: 1 KiB. Default: 16384 KiB.
Concurrent peer connection limit
New incoming peer connections are rejected when this many incoming and outgoing transfer or private-message connections already exist. Hub connections are not included. Minimum: 1. Default: 512.
Incoming connection flood window
Time span used to count incoming peer connection attempts from each IP address. The allowed burst is derived from the multi-connection upload setting. Minimum: 1 millisecond. Default: 10000 milliseconds.
Global UDP rate window
Time span used by the global incoming search-result UDP packet limiter. Minimum: 1 millisecond. Default: 1000 milliseconds.
Global UDP packet limit
Maximum incoming search-result UDP packets processed during the global UDP rate window. Minimum: 1. Default: 2000.
Per-peer UDP packet limit
Maximum incoming search-result UDP packets processed from one IP address during the per-peer UDP rate window. Minimum: 1. Default: 500.
Per-peer UDP rate window
Time span used to count incoming search-result UDP packets separately for each IP address. Minimum: 1 millisecond. Default: 10000 milliseconds.
Tracked UDP peer limit
Maximum number of IP addresses retained by the per-peer UDP limiter. New addresses are ignored while the table is full and no expired entries can be removed. Minimum: 1. Default: 4096.
Encrypted UDP packet limit
Maximum encrypted search-result UDP packet accepted for decryption. Valid packets must also be at least 32 bytes and aligned to a 16-byte AES block. Minimum: 32 bytes. Default: 4096 bytes.
Stored encrypted UDP key limit
Maximum recent search encryption keys retained for decrypting SUDP results. Oldest keys are discarded first. Minimum: 1. Default: 64.
Generated partial file list limit
Maximum uncompressed XML size generated in response to a partial file-list request, in KiB. Minimum: 1 KiB. Default: 65536 KiB.
